# Deployment

Deploy YeneSchool to production using Docker, nginx, and the recommended infrastructure setup.

## Docker Deployment

The recommended way to deploy YeneSchool is with Docker Compose.

### Production

```bash
docker compose up -d --build
```

### Verify Deployment

```bash
docker compose ps
docker compose logs -f
```

The application is available at `http://localhost:8000`.

## Docker Compose Architecture

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   nginx      │     │   Backend   │     │  PostgreSQL │
│  :8000       │────▶│  :8001      │────▶│  :5433      │
│  Frontend    │     │  NestJS     │     │             │
│  :3000       │     │  + Redis    │     │             │
└─────────────┘     └─────────────┘     └─────────────┘
```

## Environment Configuration for Production

### Backend (.env)

```env
DATABASE_URL="postgresql://user:securepassword@postgres:5433/sms"
JWT_SECRET="your-strong-secret-key"
REDIS_URL="redis://redis:6379"
NODE_ENV="production"
```

### Frontend (.env.local)

```env
NEXT_PUBLIC_API_URL=/api/proxy
```

## nginx Configuration

The nginx configuration handles:

- **Reverse proxy** — Routes traffic to frontend and backend
- **SSL termination** — HTTPS support
- **Static file serving** — Frontend assets
- **Rate limiting** — API request throttling

## PostgreSQL Configuration

```bash
npx prisma migrate deploy
```

## Health Checks

Monitor the deployment with health checks:

- **Frontend**: `http://localhost:8000/health`
- **Backend API**: `http://localhost:8001/health`
- **PostgreSQL**: Check port `5433`
- **Redis**: Check port `6379`

> [!WARNING]
> Always use strong secrets and never expose database or Redis ports directly to the internet. Use Docker network isolation.
